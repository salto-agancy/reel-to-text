# Roadmap

Порядок: V1 Telegram → дать 5–20 людям → посмотреть, пользуются ли вообще → V2 MCP → V3 iPhone.

После V1 следующие версии — дешёвые надстройки: ядро, получение ролика, Deepgram, кэш и ошибки уже есть.

## Текущая стратегия

V1 заморожена → открытый тест → статистика → только потом V2.

Новых функций в V1 не добавляем, только исправления. Решение о V2 принимаем, когда в `events` наберётся 20–50 реальных запросов от разных людей. Вопросы, на которые должны ответить данные:

- возвращаются ли люди повторно или пробуют один раз;
- какая доля ошибок и каких (`error_type`): если много `provider_unavailable`, чинить надо источник Instagram, а не делать MCP;
- сколько длится платная расшифровка (`processing_ms`) и как часто срабатывает запасной путь (`stt_path=upload`);
- какая длина роликов (`duration`): хватает ли лимита 5 минут;
- доля кэша (`cache_hit`): присылают ли люди одни и те же ролики.

## V1. Telegram-бот ✅ (заморожена)

Сделано:

- ядро `ReelToText` и провайдеры HikerAPI, yt-dlp, Deepgram;
- основной путь «Deepgram сам забирает MP4 по ссылке» и запасной «скачать → отправить файл → удалить»;
- бета-доступ по списку ID, лимиты в час и в сутки, лимит длины ролика, таймауты;
- кэш по shortcode и защита от двойной оплаты одного ролика;
- длинный текст: разбивка на сообщения или `.txt`;
- systemd + пульс + автоперезапуск, `deploy/deploy.sh`;
- тесты без сети и ключей (`pytest`).

Добавлено перед открытым тестом:

- таблица `events` со статистикой без содержимого транскриптов, `/stats` и `python -m reel_to_text stats`;
- общий суточный потолок `GLOBAL_DAILY_LIMIT`;
- бот открыт для всех (`ACCESS_MODE=open`).

Решения владельца от 23.09.2026:

- HikerAPI не пополняем, тест идёт на бесплатном запасе (96 запросов). Когда он кончится, бот переключится на yt-dlp, а с сервера тот быстро упирается в 429. Люди увидят «Instagram сейчас не отдаёт ролик», в статистике это `error_type=provider_unavailable`. Это сигнал решать с пополнением;
- общий потолок `GLOBAL_DAILY_LIMIT=50` оставляем;
- английский ролик, длинный текст и приватный аккаунт вживую проверяют бета-тестеры, результат смотрим в `events`.

Что смотреть на бете:

- сколько расшифровок в день на человека (`/stats`, журнал `requests`);
- как часто срабатывает запасной путь (`stt_path=upload` в логах);
- какие ошибки видят люди (`fail ... code=` в логах).

## V2. MCP ⏳

Инструмент `transcribe_instagram_reel(url) -> Transcript`. Подробно: [MCP.md](MCP.md).

Шаги:

1. `interfaces/mcp/server.py` на официальном Python SDK `mcp` (FastMCP), транспорт streamable-http.
2. Внутри только `build_core(settings)` и вызов `core.transcribe(url, requester="mcp:<client>")`.
3. Авторизация: Bearer-токен из env; для claude.ai-коннектора — OAuth по тому же шаблону, что у остальных MCP на сервере.
4. Публикация через уже работающий Cloudflare Tunnel.
5. Тест: в Claude Code «дай тезисы этого Reel: <ссылка>».
